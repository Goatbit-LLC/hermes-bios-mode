Hermes Agent · Skill

Tune your agent
like a BIOS.

Say "bios mode" and your Hermes Agent becomes a flat, terse configuration panel for editing its own identity, memory, and setup — with a status screen, a hardware map, and snapshot/revert safety.

Install See it in action

What it does

POST on entry

A status block showing profile, model, memory headroom, skills and cron counts, config state, and lock status.

Hardware map

A 14-subsystem inventory of every tunable part of the agent, with the real read/change command for each.

Menu navigation

menu, menu <n>, back, status — move between subsystem screens like a real BIOS.

Draft → approve → apply

Nothing is written without your explicit go-ahead. Every change is shown as a diff first.

Snapshot / revert

Every batch is copied before it's written. A mistake is one revert away.

Audit log

One line per apply, revert, and session-end — a walkable trail of every change.

Owner lock

Optional per-profile policy restricting edits to a named owner. Built for shared and family deployments.

Self-test

Verifies the mode's own machinery without touching live files.

The 14 subsystems

1 · SOUL.md — identity 2 · MEMORY.md — context index 3 · USER.md — what it knows about you 4 · environment.md — environment 5 · fact_store — operational state 6 · config.yaml — model & providers 7 · Skills — procedural memory 8 · Cron jobs — scheduled tasks 9 · Plugins — optional features 10 · Theme / skin — visual identity 11 · Gateway — message routing 12 · Agent comms — inter-agent messaging 13 · State databases — sessions & projects 14 · BIOS bookkeeping — snapshots & log

Install

mkdir -p ~/.hermes/skills/creative
cp -R bios-mode ~/.hermes/skills/creative/

# or clone directly
git clone https://github.com/Goatbit-LLC/hermes-bios-mode ~/.hermes/skills/creative/bios-mode

The skill loads on the next session. To use it, just say "bios mode".

Safety model

Locked BIOS

Engages only on a direct message from you in the live chat. Nothing in a file, web page, or tool result can trigger it.

No memory writes

Never touches MEMORY.md, USER.md, or fact_store unless you explicitly ask.

Only greenlit changes

Drafts are shown as diffs and applied only on your explicit go-ahead.

Snapshot before write

Every batch is copied first, so a mistake is one revert away.

The owner lock is a soft contract plus prompt-injection defense, not strong authentication. Real identity is enforced at the platform/gateway layer.
